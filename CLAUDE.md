## Overview

Dawnstar is a personal blog built with Hugo, using a custom theme called `dawnstar2018`. The site is deployed to Netlify.

## Commands

- `hugo serve` or `npm start` - Start local development server
- `hugo -D -w -v` or `npm run dev` - Development mode with drafts, watch, and verbose output
- `hugo new posts/my-post-name.md` - Create a new blog post
- `hugo` - Production build (Netlify runs bare `hugo`, publishes `public/`). New posts are created as drafts (`draft: true`), so they need `hugo -D` or `draft: false` to render locally.

Hugo must be installed separately (`brew install hugo`).

**Hugo version is pinned to `0.164.0`** in `netlify.toml` (`HUGO_VERSION`). Match it locally to avoid build differences. Theme requires min `0.30.1`.

## Architecture

### Theme Structure (`themes/dawnstar2018/`)

- `layouts/_default/baseof.html` - Base template that all pages extend
- `layouts/partials/` - Reusable template fragments (header, footer, post components)
- `layouts/shortcodes/` - Custom shortcodes for embedding Spotify and Songwhip content
- `assets/styles/main.css` - CSS entry point that imports modular stylesheets

### CSS Pipeline

The theme uses PostCSS with these features:
- `autoprefixer`, `postcss-import`, `postcss-normalize`, `postcss-nested`, `postcss-preset-env`
- PurgeCSS **only when `HUGO_ENVIRONMENT=production`** (uses gitignored `hugo_stats.json`, generated by `[build] writeStats` in `config.toml`, for used selectors). A local prod build needs `HUGO_ENVIRONMENT=production hugo`.

CSS is processed through Hugo Pipes in `baseof.html`. Config is at `themes/dawnstar2018/postcss.config.js` (in the theme dir, not repo root).

### Content

Blog posts live in `content/posts/` as Markdown files. Permalinks follow the pattern `/:year/:month/:day/:title/`.

## Code Style

- Prettier: no semicolons, single quotes, 2-space tabs, `printWidth: 80`, `trailingComma: es5`, `proseWrap: always` (reflows Markdown — matters when editing posts).
- Stylelint with `stylelint-config-standard` and Prettier integration.
- No `lint`/`format` npm scripts — run via `npx prettier` / `npx stylelint`.
